# CanSat 2輪走行EKF MATLABシミュレーション

`EKF_MATLAB_simulation_requirements.md`（状態遷移・観測モデル・EKF予測/更新の数式）を
土台に、出発点から約50m先の目的地へ向かう目的地誘導シナリオを実装したもの。
`run_goal_directed_simulation.m` を実行すると、Phase0（静止）→ キャリブレーション走行
（直進のみでGNSS変位から初期方位角を推定）でEKFを初期化した後、方向転換のたびに
**その時点のEKF推定位置**（実機が実際に使える唯一の情報。真値は使わない）から見た
目的地への方位角を計算して機体を向け直し、1レグ分直進する、という誘導を目的地到達
まで繰り返す。EKFの推定誤差が誘導そのものに影響する閉ループシミュレーション。
外部Toolbox不使用（`randn`/`rng`/`polyfit`等コア関数のみ）。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `config_params_goal.m` | `config_params.m` を継承し、目的地・誘導ロジックのパラメータを追加 |
| `config_params.m` | 基本パラメータを一元管理（センサノイズ・機体寸法・周期など） |
| `simulate_segment.m` | 任意の初期状態から、与えた制御入力列に沿って真値・観測値を1ステップずつ生成（実行時に長さが決まる区間を継ぎ足すため） |
| `simulate_goal_directed.m` | シナリオ本体（Phase0初期化→目的地誘導ループ）。`use_encoder`フラグでEKFのエンコーダ更新有無を切り替え可能 |
| `run_ekf_over_range.m` | EKFループ本体（予測→[エンコーダ更新]→GNSS更新）を、任意区間に対して呼べる関数にしたもの。`use_encoder=false`でエンコーダ更新を丸ごとスキップ |
| `encoder_counts_to_velocity.m` | AS5600生カウント差分→ホイール周速（ラップアラウンド処理込み） |
| `latlon_to_local.m` / `local_to_latlon.m` | 緯度経度⇔ローカル座標変換 |
| `ekf_predict.m` | EKF予測ステップ |
| `ekf_update.m` | EKF更新ステップ（エンコーダ・GNSS共通の汎用形） |
| `run_goal_directed_simulation.m` | メインスクリプト（標準版、エンコーダ+GNSS） |
| `run_goal_directed_simulation_no_encoder.m` | メインスクリプト（比較版、GNSSのみ・エンコーダ更新なし） |
| `plot_results_goal.m` | 検証プロット（軌道比較の全区間図＋先頭Nレグ切り抜き図、状態誤差と±3σ） |

**誘導ロジック**: 方向転換のたびに、EKF推定位置から見た目的地への方位角を計算し、
その方向へ機体を向けてから1レグ（`leg_duration_s`秒、時間ベース）だけ直進する。目的地到達判定
（`arrival_tolerance_m`以内）もEKF推定位置基準。

**エンコーダなし比較**: `run_goal_directed_simulation_no_encoder.m` は同じシナリオ・同じ
乱数シードのまま、EKFのエンコーダ更新ステップだけを無効化する（予測+GNSS 1Hz更新のみ）。
`run_goal_directed_simulation.m` と見比べることで、車輪エンコーダによる速度フィルタリング
の有無が推定精度・誘導の安定性にどれだけ効いているかを比較できる。

**先頭Nレグの切り抜きマップ**: `plot_results_goal.m` は全区間の軌道図に加えて、
`N_LEGS_CROP`（デフォルト5）で指定した先頭レグ分だけに絞った軌道図も表示する
（走り始めの挙動を拡大して見るため、ゴール・到達許容円はこの図には出さない）。

## 実装時に補った設計判断

- **真のIMUバイアス `b_a_true`, `b_g_true`**: EKF側の過程ノイズ `sigma_rw_a`, `sigma_rw_g`
  と同じスケールでランダムウォークさせている（`simulate_segment.m`）。EKFのバイアス
  追従性能を検証する目的。固定値にしたい場合は `config_params.m` の該当sigmaを
  実質0にすればよい。
- **GNSS疑似観測値**: 真の位置→緯度経度（センサ理想出力）→位置ドメインで正規分布
  ノイズを緯度経度に変換して付加→生の緯度経度、という往復を実装。
- **エンコーダのラップアラウンド**: AS5600の12bitレジスタ差分を[-2048,2048)カウントに
  正規化してから角度差に変換。1ステップ(dt=0.05s)内に半回転を超える場合は正しく
  デラップできない前提（デフォルトパラメータでは十分な余裕あり）。
- **方向転換フェーズの走行速度**: 「左右輪駆動を想定した一定角速度」との記述から、
  その場旋回（並進速度v=0でθのみ変化）と解釈した。
- **直進の加減速モデル**: 実機は速度切替がほぼ瞬時と想定し、最初と最後の1ステップ
  (=dt=0.05s)だけ加減速するbang-bangモデル（`simulate_segment.m`内で `v_cruise/dt` の
  スパイクとして実装）。
- **旋回角**: 固定角ではなく、「EKF推定位置から見た目的地方位 − EKF推定方位角」で
  必要な旋回角を都度算出する。旋回自体はオープンループ（算出した角度÷目標角速度の
  時間だけ回頭）で、旋回中に姿勢をフィードバック補正するモデルにはしていない。
- **真の初期方位角(`theta_true_init_deg`)**: 電源投入時に機体が実際にどちらを向いて
  いるかは、静止しているPhase0中のGNSSだけではわからない（COGは移動していないと
  出ない）ため、真値側は意図的にEKFの初期の当て推量とは異なる値（デフォルト130°）に
  してある。方位角が本当に未知であることをテストするための仕掛けであり、実測すべき
  ハードウェアパラメータではない。
- **初期方位角のキャリブレーション走行**（`simulate_goal_directed.m`のPhase0直後）:
  旋回コマンドは「目的地方位 − EKF推定方位角」という*相対*角度で計算されるため、
  θの初期推定が大きく外れているとその誤差が旋回結果にそのまま乗ってしまい、GNSS
  補正だけでは収束が遅い/安定しないことがある。そこでPhase0の後、`T_calib_straight`
  秒（デフォルト10秒＝1レグと同じ長さ）だけ旋回せずに直進し、得られた複数のGNSS fix
  を時刻に対して1次回帰（`polyfit`）した傾きからEKFの初期方位角`theta_cal`とその
  推定誤差`sigma_theta_cal`を求め、それぞれx0(4)とP0(4,4)に使う。ただし`v_cruise`が
  遅くGNSSノイズが大きい設定だと、10秒の走行距離（例: 0.3m/s×10s=3m）がGNSSノイズ
  標準偏差（例: 2.12m）と同程度になり、較正の効きが弱くなる（推定誤差が1σ=40〜50°
  程度残ることもある）。実行時にコンソールへ推定値・真値との誤差・1σを表示するので、
  改善したい場合は`T_calib_straight`を伸ばすか`v_cruise`を上げると効果が大きい
  （不確かさは走行距離のほぼ逆数的に縮む）。

## 後日実測値に差し替えるべきパラメータ

`config_params.m` 内の「後日実測値に差し替え」コメント箇所（`r`, `L`,
`sigma_theta_R/L`, `sigma_a`, `sigma_rw_a`, `sigma_g`, `sigma_rw_g`, `sigma_N`, `sigma_E`,
`P0_diag`）と `config_params_goal.m` の目的地・誘導パラメータが対象。
